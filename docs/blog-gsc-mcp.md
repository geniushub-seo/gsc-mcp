## 2. Search Console 明明是免費的，為什麼還要這個

Search Console 本身沒問題，問題在**它的介面是給人「看」的，不是給人「問」的**。

三個實際痛點：

### 痛點一：一次只給你 1,000 筆

後台介面匯出上限是 1,000 列。你網站如果有三千個關鍵字有曝光，後面兩千個你根本看不到。

**這個工具走的是 API，一次可以拿 25,000 列。**

> **API 是什麼？** 就是「程式直接跟 Google 要資料」的管道。你平常是用眼睛看網頁、用滑鼠按匯出；程式走的是另一條路，那條路給的資料比網頁多很多。這也是為什麼同樣是免費的 Search Console，用程式問拿得到 25,000 列，用網頁點只有 1,000 列。

### 痛點二：比較兩個時段很痛苦

GSC 後台可以開「比較」模式，但只能看，不能好好排序、不能算「掉最多的前 20 名」。多數人最後還是匯出兩份 CSV 自己 VLOOKUP。

**這個工具有一個叫 `compare_periods` 的功能，直接幫你算好兩期差異。**

### 痛點三：品牌字把數據灌水了

你搜尋自己公司名字進來的流量，跟陌生人搜產品關鍵字進來的流量，價值完全不同。但 GSC 後台的篩選只有「包含」「等於」，以我們自己為例，你要排掉「萬智匯」「萬智匯行銷」「geniushub」「genius hub」「Genius Hub」這些變體，得手動加五、六條篩選，而且一定會漏掉沒想到的寫法。

**這個工具支援 regex（正規表示式，一種可以一次比對多種寫法的篩選語法），一條就排乾淨。**

## 3. MCP 是什麼？一句白話

**MCP（Model Context Protocol）是一個「讓 AI 可以使用外部工具」的共通規格。**

打個比方：AI 本身像一個很聰明但被關在房間裡的人，他什麼都懂，但看不到你家的數據。MCP 就是在牆上開一扇窗，讓他能伸手拿到 Search Console 的資料。

重點是這個規格是**共通的**——一次裝好，Claude、Cursor、VS Code Copilot 這些工具都能用，不用各裝一次。

### 資料會不會外流？

不會。這支程式**跑在你自己的電腦上**，不經過我們的伺服器。

流程是：你的 AI 工具 → 你電腦上的這支程式 → Google 官方 API → 資料回到你電腦。萬智匯完全看不到你的數據。

## 4. 實際用起來長怎樣（三個真實對話）

### 先講四個一直會出現的詞

下面的對話和後面的案例會一直用到這四個數字。如果你已經懂，跳過這格。

| 詞 | 白話 |
|---|---|
| **曝光** | 你的網站在 Google 搜尋結果裡**被看到**幾次。看到不等於有點。 |
| **點擊** | 有幾個人**真的按下去**進到你的網站。 |
| **CTR** | 點擊除以曝光。**一百個人看到，有幾個人點**。CTR 2% 就是一百個看到、兩個點進來。 |
| **平均排名** | 你的網頁在搜尋結果裡平均排第幾。**數字越小越好**，第 3 名比第 20 名好。 |

記住一件事就夠：**曝光多、點擊少（也就是 CTR 低），代表人家搜到你了但不想點你。** 這通常是標題寫得不對，是最容易補救的問題。

### 對話一：月報只要一句話

> **你：** 幫我做 example.com 上個月的 Search Console 月報，要有品牌跟非品牌切分
>
> **AI：** （呼叫工具查資料）
> 上月總點擊 1,234、曝光 45,678、平均 CTR 2.7%、平均排名 18.3。
> 其中品牌字佔點擊 62%，非品牌 38%。跟前一個月比，非品牌點擊成長 15%，主要來自「某組非品牌關鍵字」這組字…

![截圖：AI 回覆月報的畫面](placeholder-05-monthly-report.png)

### 對話二：找出掉最多的關鍵字

> **你：** 最近 28 天跟前 28 天比，哪些關鍵字點擊掉最多？列前 10 個
>
> **AI：** （呼叫 compare_periods）
> 掉最多的是「某產品關鍵字」，從 89 次掉到 31 次，排名從 4.2 掉到 11.8。
> 建議先檢查這頁最近有沒有改動…

### 對話三：新頁面 Google 收錄了沒

> **你：** 我上週發的這五篇文章，Google 有收錄嗎？
> （貼上五個網址）
>
> **AI：** （呼叫 inspect_url）
> 三篇已收錄，一篇「已檢索但未編入索引」，一篇 Google 完全沒抓到。
> 沒抓到那篇不在你的 sitemap 裡，建議…

> **sitemap 是什麼？** 一份你交給 Google 的網址清單，告訴它「我家有這些頁面，記得來看」。大部分網站系統（WordPress 之類）會自動幫你產生。不在清單裡的頁面，Google 比較晚才會發現。

## 5. 安裝：四個步驟，大約 30 分鐘

> **先講實話，免得你做到一半才發現：** 這一段需要開終端機貼指令，**而且需要建立一個 Google Cloud 專案**。第二件事聽起來嚇人，但實際上就是點幾個網頁、不用付錢。
>
> 我們把最容易卡住的地方（步驟 2）寫得特別詳細，因為那是唯一一個「不做就完全不能用」的環節。
>
> **偷懶捷徑：** 如果你已經在用 Claude Code、Cursor 這類 AI 開發工具，直接把 GitHub 網址丟給它，說「照 INSTALL.md 幫我裝好」，它會自己處理大部分步驟。但 Google 帳號授權那步一定要你本人做。

### 步驟 0：確認你有什麼

- 一個能登入 Google Search Console 的 Google 帳號（就是你平常看數據那個）
- Mac、Windows 或 Linux 電腦
- 一個支援 MCP 的 AI 工具（Claude Desktop、Claude Code、Cursor、VS Code）
- **建立 Google Cloud 專案的權限**——個人帳號一定有；公司帳號如果被 IT 鎖住，要請他們協助

### 步驟 1：安裝程式本體

**先確認你的電腦有沒有支援。** 目前提供五個版本：

| 你的電腦 | 支援 | 安裝方式 |
|---|---|---|
| Mac（M1/M2/M3 等 Apple 晶片） | ✅ | 下面那行指令 |
| Mac（較舊的 Intel 機種） | ✅ | 下面那行指令 |
| Windows 64 位元（絕大多數 PC） | ✅ | **要手動下載，往下看 Windows 專區** |
| Linux（一般電腦 / 樹莓派等 ARM 機） | ✅ | 下面那行指令 |
| Windows ARM 版（少數輕薄機種） | ❌ 目前沒有 | 只能自己從原始碼編 |

#### Mac 與 Linux：一行搞定

打開終端機，貼這行：

```bash
curl -fsSL https://raw.githubusercontent.com/geniushub-seo/gsc-mcp/main/install.sh | bash
```

這行做的事：判斷你的作業系統 → 下載對應版本 → 核對檔案有沒有被動過手腳 → 裝到 `~/.local/bin` 這個資料夾。

**不放心的話**，先看它會做什麼再決定（加了 `--dry-run` 就只印步驟、不真的動手）：

```bash
curl -fsSL https://raw.githubusercontent.com/geniushub-seo/gsc-mcp/main/install.sh | bash -s -- --dry-run
```

#### Windows：要手動下載

上面那行是寫給 Mac 和 Linux 的指令格式，**在 PowerShell 或命令提示字元裡跑不動**。Windows 請這樣做：

1. 開 https://github.com/geniushub-seo/gsc-mcp/releases/latest
2. 下載 **`gsc-mcp-windows-amd64.exe`**
3. 把它改名成 `gsc-mcp.exe`，放到一個你記得住的資料夾（例如 `C:\Users\你的名字\gsc-mcp\`）
4. 記下**完整路徑**，後面設定要用

用 PowerShell 下載也可以：

```powershell
Invoke-WebRequest -Uri "https://github.com/geniushub-seo/gsc-mcp/releases/latest/download/gsc-mcp-windows-amd64.exe" -OutFile "$env:USERPROFILE\gsc-mcp.exe"
```

> **[需確認]** Windows 的完整流程我們沒有在真的 Windows 機器上跑過一遍。程式本身有 Windows 版、設定指令裡也有處理 Windows 的路徑，但實際體驗如何還沒驗證。**你如果是 Windows 使用者，跑完歡迎回報卡在哪。**

> **如果你裝了 Git for Windows**，可以開 Git Bash，那裡面就能跑 Mac/Linux 那行指令。

![截圖：終端機執行 install.sh 的輸出](placeholder-07-install-output.png)

### 步驟 2：建立一個 Google Cloud 專案（**最容易卡住的一步**）

先說結論：**這一步不能跳過。沒有它，後面全部會失敗。**

**用白話講這是什麼：** Google 要求每個用程式查資料的人，都要有一個「記帳編號」，這樣它才知道這些查詢是誰發出的、用了多少量。這個編號就是「Google Cloud 專案」。

不是要跟你收錢，是要能點名。就像進大樓要換證，證不用錢，但沒有就進不去。

我們實際測過：把專案設定拿掉之後查詢，Google 直接回絕：

```
The searchconsole.googleapis.com API requires a quota project,
which is not set by default.
（翻成白話：這支查詢服務需要一個「記帳編號」，而預設是沒有的）
```

#### 先回答你最擔心的兩件事

**會不會收費？** 不會。Search Console API 是免費的，這個專案存在的目的只是讓 Google 知道「這些查詢算在誰頭上」，用來計算用量。你不會被要求綁信用卡就能完成。

**「Google Cloud」聽起來很專業，我搞得定嗎？** 這一步是**點網頁**，不是寫程式。三個動作：建專案、啟用 API、記下專案 ID。

#### 實際操作

1. 開 https://console.cloud.google.com/projectcreate
2. 專案名稱隨便取（例如 `my-seo-tools`），按「建立」
3. 建好後**把專案 ID 記下來**（通常長得像 `my-seo-tools-473201`，跟名稱不完全一樣）
4. 開 https://console.cloud.google.com/apis/library/searchconsole.googleapis.com
5. 確認左上角選的是你剛建的專案，按 **Enable**（啟用）

![截圖：建立專案畫面，圈出專案 ID 的位置](placeholder-14-gcp-create-project.png)
<!-- 建議：一定要圈出「專案 ID」跟「專案名稱」的差別，這是最多人搞混的地方 -->

![截圖：Search Console API 頁面的 Enable 按鈕](placeholder-08-google-oauth.png)

> **如果你的公司有 Google Workspace**，管理員可能鎖住了個人建立專案的權限。這種情況要請 IT 幫你開一個，或請他們給你一個現成專案的 ID。

### 步驟 3：裝 gcloud 並登入

`gcloud` 是 Google 的官方命令列工具，用來完成授權：

- **macOS**：`brew install --cask google-cloud-sdk`
- **Windows**：`winget install Google.CloudSDK`
- **Linux**：下載官方安裝包後**一定要執行 `install.sh`**

> **它會下載約 713 MB，這是正常的**——那是 Google Cloud SDK 本身的大小，不是我們這支程式。我們的程式就一個檔案。看到大檔案不用擔心裝錯東西。

> ⚠️ **這一段請一定要看，Mac 和 Linux 都會中招。**
>
> gcloud 需要 Python 3.10 到 3.14 這個範圍的版本才能跑（Python 是一種程式語言，gcloud 是用它寫的）。問題是 **macOS 內建的是 3.9，太舊**，Linux 有些發行版也是。
>
> gcloud 自己帶了一份正確版本的 Python，但**只有在你執行它的安裝程式時才會裝進去**。如果你只是把壓縮檔解開就以為好了，它就會去抓系統那份太舊的，然後失敗。
>
> **最麻煩的是錯誤訊息會誤導你**——看起來像是我們這支程式壞了，其實是 gcloud 沒裝好。
>
> **我們自己也踩過這個坑**，而且是更陰險的版本：設定明明是對的，但只寫在「開終端機時才會載入」的設定檔裡。結果自己打指令都正常，一旦換成程式自動呼叫就報錯，怎麼查都查不出來。如果你遇到「我明明裝了新版 Python 它還說我是舊版」，多半就是這個。

裝好之後執行登入（會跳出瀏覽器）：

```bash
gcloud auth application-default login --scopes=https://www.googleapis.com/auth/webmasters.readonly,https://www.googleapis.com/auth/cloud-platform
```

**`webmasters.readonly` 是關鍵**——`readonly` 代表唯讀，這個授權**只能讀資料，不能改你的 Search Console 設定**。

#### 把步驟 2 的專案綁上去

登入完成後，確認專案有綁定。如果 `gcloud` 當時已經選好專案，這步通常會自動完成；沒有的話手動指定：

```bash
gcloud auth application-default set-quota-project 你的專案ID
```

> `你的專案ID` 換成步驟 2 記下來的那串（像 `my-seo-tools-473201`）。
> **[需確認]** 這條指令我們沒有在全新的機器上實測過，只驗證了「沒有綁專案一定會失敗」。若指令有出入，以 `gcloud` 當下的提示為準。

### 步驟 4：接上你的 AI 工具

```bash
gsc-mcp setup
```

這個指令會自動幫你把設定寫進 AI 工具的設定檔，並且試著列出你的網站確認有沒有通。

想先看它要改什麼再決定：

```bash
gsc-mcp setup --dry-run
```

**Claude Desktop 使用者注意**：改完設定要 **Cmd+Q 完全退出**再重開，只關視窗沒用。

![截圖：setup 執行成功，列出網站清單](placeholder-09-setup-success.png)

### 完成確認

在你的 AI 工具裡問：

> 用 gsc 的 list_sites 列出我的 Search Console 網站

有列出網站清單就成功了。

## 6. 它有哪六個功能

你不需要記這些名字，AI 會自己選。放在這裡是讓你知道**它做得到什麼、做不到什麼**。

| 名稱 | 白話說明 | 你會這樣問 |
|---|---|---|
| `list_sites` | 列出你所有能看的網站 | 「我有哪些網站？」 |
| `get_site` | 查你對某個網站的權限等級 | 「我對這個網站是什麼權限？」 |
| `query_search_analytics` | **主力功能**。查點擊、曝光、CTR、排名 | 「上個月哪些關鍵字帶最多流量？」 |
| `compare_periods` | 兩個時段對比，自動算差異 | 「這 28 天跟上 28 天比如何？」 |
| `inspect_url` | 查單頁的收錄狀態（一次最多 10 個網址） | 「這幾篇文章 Google 收錄了嗎？」 |
| `manage_sitemaps` | 看 sitemap 狀態（提交/刪除預設鎖住） | 「我的 sitemap 有錯誤嗎？」 |

### 為什麼只有六個？

別家同類工具有二十幾個功能，聽起來比較厲害，但其中一半其實是**同一個查詢的不同預設值**——例如「查詢報表」「頁面報表」「進階報表」底層都是同一支 API。

功能越多，AI 每次都要讀完所有說明，反而更容易選錯。我們把那些變體寫成一張對照表（`gsc-recipes`）讓 AI 查，效果一樣、不佔空間、不會選錯。

### 明確不做的事

- **不能幫你送出索引請求**（Google 官方 API 只開放給徵才和直播頁面）
- **不能看涵蓋範圍報表、Core Web Vitals、外部連結報表**（官方 API 根本沒有這些）
- **預設不能新增或刪除網站**（誤刪風險太高）

## 7. 直接複製就能用的 10 個問法

把 `你的網站.com` 換成你自己的網址就好。

### 基礎健檢

```
1. 列出我所有的 Search Console 網站
2. 你的網站.com 最近 28 天總點擊、曝光、CTR、平均排名是多少？
3. 你的網站.com 最近 28 天流量最高的 20 個關鍵字
4. 你的網站.com 最近 28 天流量最高的 20 個頁面
```

### 找問題

```
5. 你的網站.com 最近 28 天 vs 前 28 天，點擊掉最多的 10 個關鍵字
6. 你的網站.com 有哪些關鍵字曝光很高但點擊很少？（CTR 偏低的機會頁）
7. 你的網站.com 排名在第 8 到 20 名之間的關鍵字有哪些？（推一把就能上第一頁）
```

### 進階（這是別家做不到的）

```
8. 你的網站.com 最近 28 天，排除掉品牌字（你的品牌、Your Brand、yourbrand）之後，
   非品牌關鍵字的表現如何？
9. 幫我做 你的網站.com 上個月的完整月報，要有品牌 vs 非品牌切分
10. 檢查 你的網站.com 的索引健康度：sitemap 狀態加上首頁跟主要分類頁的收錄狀況
```

## 8. 實戰案例：22 萬曝光只換到 2,593 次點擊，問題出在哪？

> **這一段的數字全部是真的**，來自我們自己一個網站，查詢區間 2026-07-13 到 2026-08-09（28 天）。
>
> 為了不把自家的關鍵字情報送給同業，**關鍵字名稱已改成代號（關鍵字 A、B1、C1…），網域寫成 `example.com`**。所有數字、CTR、排名、變化率都未經修改——分析邏輯你照著跑就會得到一樣的推論過程。

這個案例會示範**四個回合的對話**，每一回合用到哪支工具、你該打什麼字，全部列出來。

![截圖：整個案例的對話全景](placeholder-12-case-overview.png)
<!-- 建議：把四回合對話截成一張長圖 -->

---

### 回合 1：先看整體，不要一開始就鑽細節

**你打的字：**

```
example.com 最近 28 天（2026-07-13 到 2026-08-09）的總點擊、
總曝光、CTR 和平均排名是多少？不用分關鍵字，我要整站總覽。
```

**AI 會呼叫的工具：** `query_search_analytics`
（關鍵在**不給 dimensions**，這樣才會回傳整站彙總的一列，而不是逐個關鍵字）

**實際拿到的結果：**

| 指標 | 數值 |
|---|---|
| 總點擊 | 2,593 |
| 總曝光 | 228,182 |
| CTR | 1.14% |
| 平均排名 | 10.38 |

**怎麼讀：** 平均排名 10.38 不算差，但 CTR 只有 1.14%。一般來說排名在第 10 名附近，CTR 落在 2% 到 3% 是合理的。**曝光很多、點擊很少，代表有人搜到你了，但看到標題不想點。**

這是一個「有東西可以撿」的訊號，值得往下挖。

---

### 回合 2：排掉品牌字，看真正的陌生流量

品牌字（搜「你的品牌名」找到你）本來就會點，混在裡面會把 CTR 拉高、掩蓋問題。先排掉。

**你打的字：**

```
同一個區間，排除掉品牌字（yourbrand、your brand、你的品牌中英文各種寫法），
列出點擊最高的 30 個關鍵字，含曝光、CTR、平均排名。
```

**AI 會呼叫的工具：** `query_search_analytics`
帶上 `dimensions: ["query"]` 加上 `dimension_filter_groups`，operator 用 **`excludingRegex`**

實際送出的篩選長這樣（你不用自己寫，AI 會組，但知道長怎樣有助於你檢查它有沒有做對）：

```json
{
  "dimension": "query",
  "operator": "excludingRegex",
  "expression": "(?i)yourbrand|your\\s*brand|你的品牌|你的中文品牌"
}
```

> `(?i)` 代表不分大小寫，`\s*` 代表中間可以有空格也可以沒有。
> **這就是第 2 段講的「別家做不到」的地方**——如果只有「包含」「等於」，你得手動加四條篩選，而且漏掉「Your Brand」這種寫法。

**實際拿到的結果（前 8 名）：**

| 關鍵字 | 點擊 | 曝光 | CTR | 平均排名 |
|---|---|---|---|---|
| 關鍵字 A | 374 | 49,478 | 0.76% | 6.38 |
| 關鍵字 A′ | 64 | 7,238 | 0.88% | 6.46 |
| 關鍵字 B1 | 50 | 1,368 | 3.65% | 2.07 |
| 關鍵字 C1 | 34 | 784 | 4.34% | 5.55 |
| 關鍵字 D | 31 | 2,145 | 1.45% | 4.42 |
| 關鍵字 E | 26 | 763 | 3.41% | 4.41 |
| 關鍵字 F | 25 | 1,006 | 2.49% | 4.77 |
| 關鍵字 G | 17 | 1,599 | 1.06% | 7.57 |

**問題浮出來了：**

「關鍵字 A」一個字就吃掉 **49,478 次曝光，佔全站 21.7%**，但只換到 374 次點擊，CTR 0.76%。加上有空格的「關鍵字 A′」，兩個字合計 56,716 次曝光，**佔全站曝光四分之一**。

對照下面「關鍵字 B1」——排名 2.07、CTR 3.65%。同一個網站，CTR 差了快 5 倍。

**排名 6.38 卻只有 0.76% CTR，這不正常。** 第 6 名的位置通常能拿到 2% 以上。

---

### 回合 3：這是一直這樣，還是最近才變差？

一個時間點的數字看不出方向，要拉兩期比。

**你打的字：**

```
example.com，用 2026-06-15 到 2026-07-12 當基準期，
2026-07-13 到 2026-08-09 當現況期，比較關鍵字表現，
我要看「關鍵字 A」的變化。
```

**AI 會呼叫的工具：** `compare_periods`
（**注意兩期天數必須一樣**，這裡都是 28 天。不一樣的話工具會直接回 `invalid_input` 擋下來，不會給你錯誤的比較結果）

**「關鍵字 A」實際拿到的對比：**

| 指標 | 前 28 天 | 近 28 天 | 變化 |
|---|---|---|---|
| 點擊 | 327 | 374 | **+47（+14.4%）** |
| 曝光 | 52,163 | 49,478 | −2,685（−5.2%） |
| CTR | 0.63% | 0.76% | **+0.13 個百分點**（相對 +20.6%） |
| 平均排名 | 6.38 | 6.38 | **0（沒動）** |

**怎麼讀：** 排名完全沒動，曝光小跌，但點擊和 CTR 都上升了。

意思是**這個字不是在崩，而是本來就長這樣**——CTR 低是結構性的問題，不是最近出了什麼事。而且 CTR 有在慢慢改善，代表方向對了，只是幅度太小。

---

### 回合 4：那我到底該做什麼？

**你打的字：**

```
根據上面的資料，「關鍵字 A」排名 6.38 但 CTR 只有 0.76%，
幫我分析可能原因，並給我三個具體可執行的行動。
```

**AI 會呼叫的工具：** 這一回合**不呼叫任何工具**，它用前三回合已經拿到的資料直接分析。

（如果你想再深入，可以叫它用 `query_search_analytics` 帶 `dimensions: ["page"]` 看是哪一頁在接這個字，或用 `inspect_url` 確認那頁的收錄狀態。）

**AI 給出的判斷方向大致是：**

1. **搜尋意圖不合。** 搜這組字的人想要**當場就能用的東西**，你給的是一篇要花時間讀的文章。即使排第 6，使用者掃過標題就知道「這不是我要的」，直接跳過。
2. **標題沒有給出「立刻可用」的訊號。** 排在你前面的競爭對手，標題多半帶著「線上」「免費」「一鍵」這種即時性的字眼；你的標題如果是「⋯⋯怎麼用？完整教學」，在意圖上就先輸了。
3. **可能被 Google 的搜尋結果區塊吃掉點擊。** 有些查詢 Google 會直接在搜尋頁上給答案或給互動元件，使用者根本不需要點進任何網站。這種情況下高曝光低 CTR 是結構性的，改標題也救不回全部。

**具體行動：**
- 把該頁**重排版面**：使用者要的東西放最上面，說明和教學往下移
- **改標題**，加入即時可用的訊號，並在描述裡明講「不用註冊」「不用下載」這類降低門檻的話
- **兩週後回來重跑回合 3 的 `compare_periods`**，看 CTR 有沒有動。沒動就代表是第 3 點，不是你的問題

---

### ⚠️ 這個案例裡我們差點誤判的地方

回合 3 的完整結果裡，有一批關鍵字（例如「關鍵字 X」6,363 次曝光、「關鍵字 Y」5,159 次曝光）在近 28 天顯示為 **0**，工具標記 `only_in: "a"`（只出現在基準期）。

**看起來像是「這些字的流量全沒了」，但很可能不是。**

因為我們設定一次只取前 100 名。這些字如果從第 90 名掉到第 110 名，就會**消失在結果裡並顯示為 0**，實際上流量還在。

**正確做法：** 針對懷疑的字單獨查一次，或把 `row_limit` 拉高再比。

```
把 row_limit 拉到 1000 再比一次，我要確認「關鍵字 X」是真的歸零
還是只是掉出前 100 名
```

這個坑我們自己也踩過。**看到「歸零」先別緊張，多半是排序截斷。**

### 整個案例用到的工具總結

| 回合 | 目的 | 工具 | 關鍵參數 |
|---|---|---|---|
| 1 | 整站體檢 | `query_search_analytics` | **不給** dimensions |

## 9. 看數字之前，你一定要知道的 6 個坑

這些不是我們的限制，是 **Google Search Console 本身的特性**。不知道的話很容易解讀錯。

### 坑一：資料慢 2 到 4 天

今天問「昨天表現如何」，數字幾乎一定是不完整的。看趨勢至少要往前推 3 天。

### 坑二：日期是美國太平洋時間，不是台灣時間

Search Console 算的「一天」用的是**美國西岸時間**，跟台灣差 15 到 16 小時。

所以你在台灣禮拜二早上看到的「今天數據」，其實裝的是美國西岸禮拜一的一部分。做日報的時候特別容易搞混——**不要用「今天」對帳，用完整的區間比較安全。**

### 坑三：只保留 16 個月

再往前的資料 Google 直接不給。想做年度對比，記得**每個月自己備份**。

### 坑四：總和不會等於後台總計

API 只回傳「前幾名」的資料列，不是全部。你把 1,000 個關鍵字的點擊加起來，會小於後台顯示的總點擊——這是正常的，不是有 bug。

### 坑五：「平均排名 8.3」不等於「排第 8 名」

那是**加權平均值**。可能是這個字在某些搜尋裡排第 3、某些排第 20，平均起來 8.3。不要拿這個數字跟老闆說「我們排第八」。

### 坑六：CTR 的百分點 vs 百分比

CTR 從 2% 變成 3%，是「上升 1 個百分點」還是「上升 50%」？兩種說法都對，但意思差很多。

我們的工具在對比功能裡回傳的 `ctr_delta_pp` 給的是**百分點**（`pp` = percentage point）。0.10 變成 0.125 會回傳 `2.5`，代表上升 2.5 個百分點。

## 10. 常見錯誤排解

| 你看到的訊息 | 意思 | 怎麼修 |
|---|---|---|
| 訊息裡有 **`requires a quota project`** | **沒綁 Google Cloud 專案。這是最常見的第一個錯誤** | 回步驟 2 建專案，然後 `gcloud auth application-default set-quota-project 你的專案ID` |
| `no credentials found` | 還沒登入 Google | 重跑步驟 3 的 `gcloud auth application-default login` |
| `list_sites` 回 403 | 專案沒綁、API 沒啟用、或真的沒權限（**三種都會回 403，先看上面那條**） | 依序排除：先確認專案已綁 → 再去 [Cloud Console](https://console.cloud.google.com/apis/library/searchconsole.googleapis.com) 按 Enable → 最後才懷疑帳號權限 |
| 網站清單是空的 | 這個 Google 帳號在 GSC 沒有任何網站 | 確認你登入的是**正確的**帳號（很多人有多個 Google 帳號） |
| AI 工具裡看不到 gsc 工具 | 設定沒寫成功或沒完全重啟 | Claude Desktop 要 **Cmd+Q**，不是關視窗 |
| 用了一陣子突然登入失敗 | Google 的授權過期了（改密碼、太久沒用都會） | 重跑一次登入指令就好，**不用重裝** |
| macOS 說「無法驗證開發者」 | Mac 的安全機制擋下了不是從 App Store 來的程式（不是病毒警告） | 在 Finder 找到那個檔案 → **按右鍵 → 選「打開」→ 再按一次「打開」** |

### ⚠️ 一個我們自己的缺陷，先跟你說

如果你撞上「記帳編號」那個錯誤，我們回給你的**建議是錯的**。它會叫你：

> ask the property owner to add the service account email to this Search Console property
> （請網站擁有者把「機器人帳號」的信箱加進這個網站）

**照做完全沒用。**

「機器人帳號」是給伺服器自動跑排程用的另一種登入方式，**你走的不是那條路**——你是用自己的 Google 帳號登入的。而且問題根本不在誰有沒有權限，是缺那個記帳編號。

這是我們錯誤訊息對應寫得不夠細造成的，已列入待修清單。在修好之前：**看到 `quota project` 這幾個字，就直接跳到步驟 2，忽略它給的建議。**

（順帶一提，這種「錯誤訊息把人導向錯方向」的問題，正是我們把整包東西開源的理由之一——被人用、被人罵，才會發現。）

### 特別說明：權限等級

`list_sites` 會顯示每個網站的權限等級：

- `siteOwner` / `siteFullUser` → 可以正常查資料
- `siteUnverifiedUser` → **這是「有帳號但驗證沒完成」**，查資料多半會回空的或 403。不是工具壞了，是那個網站的驗證沒做完。

## 11. 常見問題 FAQ

**Q：要錢嗎？**
完全免費，開源專案。Google Search Console 的查詢服務本身也是免費的。

**Q：安裝時要建的那個「Google Cloud 專案」會不會被收費？**
不會。它只是一個記帳編號，讓 Google 知道查詢是誰發的。查 Search Console 資料不收費，過程中也不會要你綁信用卡。**但請留意：Google Cloud 上有其他服務是要錢的，你只要照步驟 2 做（建專案、啟用 Search Console 那一個服務），不要去開其他東西就不會有費用。**

**Q：我不會寫程式，真的裝得起來嗎？**
安裝需要複製貼上四行指令。裝完之後完全不需要碰程式。如果卡住，把 GitHub 網址丟給 Claude 或 ChatGPT 問它。

**Q：資料安全嗎？我的客戶數據會不會外流？**
程式跑在你自己的電腦上，資料從 Google 直接回到你的電腦，不經過任何第三方伺服器。我們的授權要求是 `readonly`（唯讀），連改你設定的能力都沒有。

**Q：可以管理多個客戶的網站嗎？**
可以。你的 Google 帳號有權限的所有網站都會一次列出來，不用一個一個切換。

**Q：它會不會亂改我的 Search Console？**
預設全部唯讀。提交或刪除 sitemap 需要另外重新登入並開啟旗標，不會不小心觸發。

**Q：跟付費 SEO 工具（Ahrefs、Semrush）比呢？**
不一樣的東西。那些工具給你**外部估算**的排名和對手資料；這個給你 Google 官方的**你自己網站的真實數據**。兩者互補，不衝突。

**Q：支援哪些 AI 工具？**
Claude Desktop、Claude Code、Cursor、VS Code + Copilot。任何支援 MCP 標準的工具都可以。

**Q：Windows 可以用嗎？**
可以，但**不能用那行一鍵安裝指令**，要自己去下載頁抓 `gsc-mcp-windows-amd64.exe`（步驟 1 有寫）。程式本身有 Windows 版，登入和設定的流程都一樣。

只有一種 Windows 不行：**ARM 架構的機種**（少數輕薄筆電）。目前沒有出那個版本。分不清自己是哪種的話，絕大多數 PC 都是可以用的那種。
